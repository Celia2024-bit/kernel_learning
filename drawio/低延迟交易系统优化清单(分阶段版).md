# 低延迟交易系统优化清单(分阶段版)

### ——按"在哪个阶段做"重新组织,从镜像构建到运行时

---

## 总体思路

同样的优化手段,发生在完全不同的时间点:有的是**镜像构建时**一次性定好的(比如内核怎么编译),有的是**系统启动时**通过内核参数定的,有的是**应用启动前**由运维手动配置的,有的是**应用初始化时**代码里做的,还有的是**运行时**每一刻都在生效的行为模式。

把这些按阶段分开的价值在于:排查问题时能立刻知道"这一层出了问题该去哪改"——是改镜像、改 grub 启动参数、改系统配置脚本,还是改应用代码。

```
阶段一:镜像构建(Build Time)
        ↓
阶段二:系统启动(Boot Time / 内核参数)
        ↓
阶段三:系统运行前配置(Post-Boot,应用启动之前)
        ↓
阶段四:应用初始化(App Init,代码启动时执行一次)
        ↓
阶段五:运行时(Runtime,应用主循环持续执行)
```

---

## 阶段一:镜像构建阶段(Build Time)

这一阶段的改动**编译进镜像里**,系统装好之后不会再变,除非重新构建镜像。

| 改动                       | 内容                                                               | 在哪改                                      |
| ------------------------ | ---------------------------------------------------------------- | ---------------------------------------- |
| 精简 driver / application  | 移除不需要的驱动和后台服务,减少潜在的中断源和后台调度对象数量                                  | 镜像构建脚本(裁剪安装包列表)                          |
| 内核抢占模型编译为 `PREEMPT_NONE` | 内核态代码执行时不会被主动打断,省去 `PREEMPT_VOLUNTARY`/`PREEMPT` 模型里"要不要抢占"的检查开销 | 内核编译配置(`CONFIG_PREEMPT_NONE=y`),需要重新编译内核 |

> ⚠️ 澄清一下:这一步**不能消灭硬件中断本身**——只要机器上还有网卡、磁盘、时钟等基础硬件,该产生的中断依然会产生。这一步解决的是"从源头减少中断的种类和数量",真正决定"中断投递到哪个核心"依赖阶段二的 IRQ affinity。
> 
> `PREEMPT_NONE` 之所以适合这套方案,是因为**建立在阶段二完整隔离核心的前提之上**——核心上压根没有别的 task 需要抢占,所以抢占检查的开销纯属浪费。如果没做隔离,`PREEMPT_NONE` 反而可能让内核代码长时间占着 CPU,造成更差的最坏情况延迟。

---

## 阶段二:系统启动阶段(Boot Time / 内核启动参数)

这一阶段的改动写在 **grub 启动参数**里,每次系统重启时生效,不需要重新构建镜像,但需要重启机器。

| 参数                                         | 作用                                             |
| ------------------------------------------ | ---------------------------------------------- |
| `isolcpus=4-7`                             | 把 4-7 号核心从调度器的公共池里摘出来,普通 task 不会被自动调度上来        |
| `irqaffinity=0-3`                          | 把硬件中断默认投递范围限制在 0-3 号核心,不让中断投递到隔离核心             |
| `nohz_full=4-7`                            | 关闭 4-7 号核心上的周期性时钟中断(timer tick)                |
| `rcu_nocbs=4-7`                            | 把 4-7 号核心的 RCU 回调处理转移到其他核心                     |
| `workqueue.unbound_cpus=0-3`               | 限制不绑定特定核心的内核工作线程(unbound kworker)只能在 0-3 号核心运行 |
| `isolcpus=managed_irq,domain,4-7`(进阶,较新内核) | 连驱动自行选择投递的 managed IRQ 也排除在隔离核心之外              |

> ⚠️ 例外情况:**`ksoftirqd` 和 per-CPU bound kworker 是每个核心天生自带、无法被参数排除的内核线程**。它们权限上从未被排除,但只要没有触发它们工作的事件(比如中断已经被 `irqaffinity` 挪走,不会在该核心产生 softirq),它们就会一直处于休眠状态——消除的不是"它们能不能来"的资格,而是"有没有事情让它们来"的触发源。

---

## 阶段三:系统运行前配置(Post-Boot,应用启动之前)

系统已经启动,但交易程序还没跑起来之前,由运维脚本或系统服务完成的配置。这一阶段通常需要 root 权限,写在系统初始化脚本(如 systemd service 或 rc.local)里。

| 配置                                           | 内容                                                                                              |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 关闭 `irqbalance` 服务                           | `irqbalance` 默认会自动把中断"均衡"到所有核心(包括隔离核心),会覆盖掉 `irqaffinity` 的效果,必须关掉(`systemctl stop irqbalance`) |
| 手动核对每个中断号的 `/proc/irq/<n>/smp_affinity_list` | 确保关键中断(网卡等)明确绑定在非隔离核心上,不依赖启动参数的默认行为                                                             |
| 彻底关闭 swap                                    | `swapoff -a`,或系统层面不配置 swap 分区/文件,防止任何意外的 swap-in/swap-out 造成毫秒级延迟抖动                             |

> 这一阶段和阶段二的区别在于:阶段二的参数是内核启动那一刻就锁定的默认策略,阶段三是系统已经跑起来之后、针对具体设备和服务做的精细调整(比如某块网卡的具体中断号是多少,只有系统跑起来之后才能查到)。

---

## 阶段四:应用初始化阶段(App Init,代码里执行一次)

交易程序**启动时**执行的一次性设置代码,不在主循环里重复执行。

### 4.1 CPU 绑定与调度策略

```c
// 把关键线程绑定到隔离核心(对应阶段二 isolcpus=4-7 里的某个核心)
cpu_set_t cpuset;
CPU_ZERO(&cpuset);
CPU_SET(4, &cpuset);
sched_setaffinity(0, sizeof(cpuset), &cpuset);

// 设置调度策略为 SCHED_FIFO,高优先级
struct sched_param param;
param.sched_priority = 99;
sched_setscheduler(0, SCHED_FIFO, &param);
```

- **关键交易线程**:绑定到隔离核心,`SCHED_FIFO`(核心上没有竞争者,`SCHED_NORMAL` 也可以)。
- **重要但不常触发的线程**(风控检查、撤单逻辑等):`SCHED_FIFO` + 高优先级,保证一旦被唤醒能立即抢占。

> ⚠️ 风险提示:`SCHED_FIFO` 高优先级线程设计不当(死循环不让出)会饿死同核心上的其他任务;Linux 默认的 `sched_rt_runtime_us` 保护机制会限制 RT 任务最多用 95% CPU,若要完全解除需手动设为 `-1`,需谨慎评估。

### 4.2 内存预分配与锁定

```c
// 1. 一次性从系统申请一大块内存池,运行时不再调用 malloc/free
void *pool = mmap(NULL, POOL_SIZE, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS | MAP_HUGETLB, -1, 0);

// 2. memset prefault:强制触发 minor fault,让物理页面提前分配好
memset(pool, 0, POOL_SIZE);

// 3. mlockall:锁定当前及未来的内存,防止被 swap(注意不带 ONFAULT)
mlockall(MCL_CURRENT | MCL_FUTURE);
```

- **内存池一次性分配**:自定义内存池/对象池,运行时不再调用 `malloc`/`free`(glibc 的 malloc 会加锁,且可能触发 `brk`/`mmap` 等 syscall)。
- **Huge Pages**:用 `MAP_HUGETLB` 或 hugetlbfs 把关键 buffer 映射成 2MB/1GB 大页,大幅减少所需要的 TLB entry 数量,提高常驻 TLB 的概率(不是 100% 保证,仍需阶段二三的隔离配合减少 TLB 冲刷事件)。
- **Prefault(memset)**:消除运行时首次访问 buffer 时的 minor fault。
- **mlockall(不带 ONFAULT)**:防止内存被换出;若不想锁住整个进程地址空间,可只对关键 buffer 用更细粒度的 `mlock()`。

### 4.3 无锁数据结构的 Cache Line 对齐

```c
struct alignas(64) PaddedIndex {
    std::atomic<uint64_t> value;
    char padding[64 - sizeof(std::atomic<uint64_t>)];
};

struct RingBufferControl {
    PaddedIndex head;  // 独占一条 cache line
    PaddedIndex tail;  // 独占另一条 cache line
};
```

- 无锁 ring buffer 的 `head`/`tail` 指针、per-core 计数器等跨核心共享的变量,用 `alignas(64)` 强制独占 cache line,消除 **false sharing**——否则不同核心会因为"凑巧共享同一条 cache line"而反复触发 MESI 一致性协议的 invalidation,抵消无锁化带来的收益。

## 阶段五:运行时阶段(Runtime,主循环持续执行)

交易程序**跑起来之后**,每一刻都在生效的行为模式,不是一次性设置,而是贯穿整个生命周期的执行方式。

| 行为                      | 内容                                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Busy-polling            | 关键线程用非阻塞方式忙轮询数据(`recv(..., MSG_DONTWAIT)` 循环),而不是阻塞式调用,避免因线程挂起/唤醒触发的 context switch。**前提**:必须运行在阶段二三隔离好的专属核心上,且核心上只有这一个线程 |
| Kernel Bypass(更激进的替代方案) | 用 DPDK、Solarflare OpenOnload、Mellanox VMA 等技术,让数据直接从网卡 DMA 到用户态,彻底跳过内核网络协议栈,而不只是"把 syscall 挪到另一个线程"                       |
| 后台线程处理非关键 syscall       | 日志、监控等非关键操作交给专门的后台线程,通过阶段四搭建好的无锁 ring buffer 与关键线程通信,关键线程本身不进内核                                                           |

---

## 完整链路总览

```
【阶段一:镜像构建】
  精简 driver/application → 内核编译为 PREEMPT_NONE
                ↓
【阶段二:系统启动(grub 参数)】
  isolcpus=4-7  +  irqaffinity=0-3  +  nohz_full=4-7
  +  rcu_nocbs=4-7  +  workqueue.unbound_cpus=0-3
                ↓
【阶段三:系统运行前配置(运维脚本)】
  关闭 irqbalance → 手动核对每个中断号的 smp_affinity → swapoff -a
                ↓
【阶段四:应用初始化(代码启动时执行一次)】
  CPU affinity 绑定关键线程到隔离核心 + SCHED_FIFO 高优先级
  → 内存池一次性分配 → memset prefault → mlockall(不带ONFAULT)
  → huge pages → 无锁 ring buffer 做 cache line 对齐(消除 false sharing)
                ↓
【阶段五:运行时(主循环持续执行)】
  关键线程 busy-polling(或 kernel bypass)
  → 非关键 syscall 交给后台线程,通过无锁 ring buffer 通信
```

**核心思想不变:** 每一层都是在用可控的资源(多余 CPU 占用、多余内存占用、重启和配置的代价)去换取延迟的确定性。区别只是——现在你清楚知道每一项改动**该动哪个文件、该在哪个时间点生效**,而不是把所有优化混在一起。
